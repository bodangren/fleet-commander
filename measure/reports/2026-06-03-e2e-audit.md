## Convex Manifest Gap (root cause for ~40% of P0 findings)

Four functions referenced by frontend code do not exist in the deployed Convex manifest at `127.0.0.1:3210`. Verified with direct `curl` against `/api/query`:

| `module:function` | Referenced from | Routes affected |
|---|---|---|
| `portfolio:getPortfolioHandler` | `frontend/src/hooks/usePortfolioData.ts:31` (used by `PortfolioPage` + `PortfolioRedirect`) | `/`, `/portfolio`, `/tasks/timeline` (catchall→`/`), `/nonexistent-*` (catchall→`/`) |
| `projects:listProjects` | `frontend/src/lib/useConvexData.ts:199` (used by `useConvexProjectsTransformed` → `useFleetData` → every route) | 16 of 25 static routes |
| `governanceEvents:getGovernanceEvents` | `useConvexData.ts:496` | `/ops` |
| `agentTemplates:listTemplatesHandler` (+ `seedDefaultTemplatesHandler`, `createTemplateHandler`) | Bun proxy `GET /api/agent-templates` → Convex | `/agent-templates`, `/agent-templates/*/edit` |

Convex functions confirmed working at audit time: `kanban:getSprintsByProjectHandler`, `kanban:getActiveSprintHandler`, `projects:listProjectsHandler` (note: different from broken `projects:listProjects`), `agents:listAgentsHandler`.

**Verbatim error string** (captured from Convex websocket):
```
[CONVEX Q(portfolio:getPortfolioHandler)] [Request ID: ecd2cb4ff6daa7b3] Server Error
Could not find public function for 'portfolio:getPortfolioHandler'. Did you forget to run `npx convex dev`?
  Called by client
```

## What's working well

- Dark theme is consistent across all 25 static pages — no visual regressions or layout breakage observed.
- Most empty states are friendly (`/blockers`, `/agents`, `/providers`, `/retrospectives`, `/notifications`, `/alerts`, `/ops/monitor`, `/performance`).
- Settings (general/providers/websocket) form actually persists via `PUT /api/settings`.
- `/ops/simulate` form correctly POSTs to `/api/policy/simulate` and renders the 400 error inline.
- 17 agents render correctly on `/agents`; per-card "Edit" button correctly navigates to `/agents/<name>/edit`.
- Invalid agent IDs (`/agents/no-such-agent/edit`) and invalid template IDs both show a "not found" pill — no crash. Only the project and task deep-links lack this nicety (see P0 #10, P2 #23).
- Vite proxy is working — `/api/*` correctly forwards to pivot :8081.
- **Zero `console.error`** observed anywhere — every observed error reaches the user as an *unhandled Promise rejection* on the Convex client, which is why missing functions cause silent "Loading…" rather than red console output. This makes P0 #1 hard to spot in browser DevTools without a network/WS filter.

---

## Top 3 fixes that unblock the most surface area

1. **Push the missing Convex functions** by running `npx convex dev` (after manually upgrading the local backend binary so the CLI doesn't prompt). Resolves: P0 #1, #2, P1 #16, #17, the `/` hang, the catchall→`/` hang via P0 #3, and silences 16/34 routes' rejection noise.

2. **Wire `Save Agent` in `AgentEditorPage`** and remove or fix the broken `Clone` (which has an infinite re-render loop). Resolves: P0 #4, #5 — restores the entire agent-creation workflow.

3. **Add `loading | error | empty` triage to the 5 stuck pages** (`/history/sprints`, `/history/agents`, `/history/tasks`, `/pipelines`, `/ops/optimize`). Pattern is identical in all 5 — `if (data === undefined && hasErrored) return <ErrorState />; if (data?.length === 0) return <EmptyState />`. Resolves: P0 #8, #9, P1 #17.
